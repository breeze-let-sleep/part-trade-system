## 自动化工程实测验证（重要结论）

在本机对 `part-trade-system-api-autotest` 做了真实试跑，结论：

- `python -m compileall -q .` 通过，退出码 0。
- `pytest --collect-only --env test` → **49 tests collected**，无导入/收集错误。`--env` 自定义参数、conftest fixture 链均正常。
- `pytest -m smoke` 实跑 → 框架端到端可用（加载配置 → 建 Session → 发请求 → 解析响应 → 断言层输出自定义中文报错）。
- 唯一失败原因是**后端未启动**：`GET http://localhost:8080/code` 返回 **502 `upstream connect failed: 由于目标计算机积极拒绝，无法连接。(os error 10061)`**。注意 8080 端口上有一个反代/网关在监听（能返回 502），但上游 Spring Boot 服务没起。
- 因此：代码本身没有阻断性缺陷，缺的只是运行环境。简历若要写实测数据，必须先起后端再跑一轮。
- 环境依赖已装（pytest/requests/PyYAML/allure-pytest/PyMySQL，装在 managed Python 3.13.12 里），下次可直接复用。
